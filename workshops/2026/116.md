## Abstracts

### Implementation and Evaluation of a Language-Independent JIT Compiler Framework for Dynamic Languages (Hinata Toma)

Just-in-time (JIT) compilation is a common technique for accelerating dynamic programming languages.
However, mature language implementations tend to be large, and retrofitting a JIT compiler onto an
existing interpreter is difficult, partly because of the need to maintain compatibility. Reimplementing
an interpreter from scratch is an alternative, but conforming to the official language specification
requires substantial effort. In this talk, we propose a system that yields a JIT-enabled language
implementation without reimplementing the existing interpreter. The proposed system takes an interpreter
compiled to WebAssembly, traces the executed WebAssembly instruction sequences, and JIT-compiles them.
To use the system, a developer only needs to annotate the locations of backward jumps that form loops
in the interpreter's source code. The system is therefore applicable to any language implementation
written in a language that can be compiled to WebAssembly. We applied the proposed system to PUC-Rio Lua,
QuickJS, CRuby, and CPython, the interpreters of Lua, JavaScript, Ruby, and Python, respectively.
On a benchmark suite of nine programs implemented in each of the four languages (36 cases in total),
the proposed system ran faster than the implementations obtained by compiling the same source code
directly to machine code in 19 cases.

### Title TBA (Midori Sugaya)

In realizing robots that coexist with humans, there is growing demand for advanced robots capable of
working collaboratively with people. Such robots are expected to make extensive use of AI technologies.
This talk discusses what is required to develop useful applications that effectively leverage AI. As an
example of applications integrating middleware and AI, we introduce our research and development of robotic
systems for elderly care. We also discuss the importance of appropriate programming languages and software
frameworks for building advanced AI-powered robotic applications.

### Persistent Signals: Reactive State That Outlives the Program (Tomoyuki Aotani)

Signals are the standard abstraction for state that changes over time, but they are transient: past
values are discarded or leak into memory, and stop at the process boundary. This talk introduces persistent
signals, which treat a time-series database as part of the language runtime, so every update is recorded and
past values stay queryable. Signal classes group persistent signals into dynamically instantiable, synchronized
units. Information sources may be distributed, with time consistency recovered after packet loss; data structures
may evolve across schema versions; and transactions may mix consistency levels per signal.

### PhysiCode Builder: Rapid Prototyping of Physical Syntax for Programming Languages (Kenji Hisazumi)

Programming languages are usually prototyped as text, making it difficult to explore how alternative
physical representations affect learnability and interaction. This talk presents PhysiCode Builder,
a framework for rapidly prototyping tangible programming languages from modular specifications. Its
metamodel separates abstract syntax—such as sequencing, branching, and data—from concrete physical syntax,
including block shape and visual markers. Users select reusable feature modules, after which the framework
generates 3D-printable blocks and TopCode-based recognition software. We discuss the framework as an
experimental platform for comparing language designs and physical notations, and illustrate how new tangible
language variants can be produced in minutes rather than through weeks of bespoke development.

### Pabst: Annotate your TypeScript and find bugs! (Jesse Alama)

Property-based testing is an approach to software testing in which one validates a program against properties
it is intended to have. Sorting an array, for instance, ought to be an idempotent operation, which can be easily
expressed as a universally quantified logical statement. [Pabst](https://github.com/jessealama/pabst) is a tool
for annotating pieces of TypeScript programs with properties. It is effectively an alternative front-end to
Nicolas Dubien's [fast-check](https://fast-check.dev/), but restricted to TypeScript programs annotated,
with JSDoc-style comments, in its own little language for properties. When Pabst runs, it attempts to find
counterexamples to the asserted properties. Pabst has found a number of bugs, even in programs that had 100%
unit test coverage, thereby enabling TypeScript programmers to experience the
[unreasoanble effectiveness of property-based testing](https://proofsandintuitions.net/2026/05/18/property-based-testing-specifications/).
